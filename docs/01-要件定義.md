# 01. 要件定義

## 1. 背景と課題

現職は人手が足りず、人材育成が十分にできていない。

- 「誰が」「どの業務を」習得しているかが分からない
- そのため、新人が業務を覚えるときに、誰に聞けばよいか、誰が教えられるかが見えない
- 教えられる人がいても、指導が特定の人に偏る、または行われない

## 2. 目的

スキルの習得状況を可視化し、**習得済みの人が新人を指導できる状態**をつくる。
少ない人数でも、スキルの習得を回せるようにする。

## 3. 開発方針

| 段階 | 内容 |
|---|---|
| 今回(第1段階) | **単一ユーザー**。自分のスキルだけを管理するスキルボードを作る |
| 将来(第2段階以降) | 複数ユーザー化。習得済みの人を「指導できる人」としてスキルごとに検索できるようにする |

第1段階では「自分のスキルの習得状況を1画面で管理できること」を完成させる。
第2段階に進めるよう、データの構造は拡張しやすい形にしておく。

## 4. 対象ユーザー

- 第1段階: スキルを管理する本人(1人)
- 将来: 現場のスタッフ全員(習得済みの人、これから習得する人、新人)

## 5. スコープ

### 5.1 今回やること

- 3つの状態(未習得 / 習得中 / 習得済み)でスキルを管理するボード
- スキルの追加・編集・削除
- スキルの列間の移動(ドラッグ&ドロップ)
- 列の追加と名前変更
- 習得日の自動記録

### 5.2 今回やらないこと(将来の拡張)

- **列の削除**(列を消すと中のスキルの扱いが複雑になり、誤操作でデータが崩れやすいため、行わない)
- ユーザー認証、複数ユーザー
- 指導できる人の検索
- チーム全体のスキル一覧、不足しているスキルの可視化
- 期限の通知・リマインド
- スマートフォン専用の画面(対応は最低限にとどめる)

## 6. 成功の基準

- 1画面のなかで、スキルの登録から習得までの状態を管理できる
- 習得済みにした日が、手入力なしで正しく残る
- ブラウザを閉じて開き直しても、データが保持される
- AWS の無料利用枠の範囲内で公開でき、課金が発生しない

## 7. 制約

| 項目 | 内容 |
|---|---|
| 技術(スクール指定) | フロントエンド: Next.js / バックエンド: Ruby on Rails / DB: MySQL / デプロイ: AWS(EC2 + RDS) |
| コスト | AWS の無料利用枠内で運用し、課金を一切発生させない。このアカウントでは t2.micro が無料枠の対象外のため、EC2 は t3.micro を使う |
| 規模 | 前回のトレロ風タスク管理アプリと同等レベル |
| 進め方 | ドキュメント作成 → 承認 → 実装 の順で進める |

## 8. 用語

| 用語 | 意味 |
|---|---|
| スキル | 習得したい、または習得した業務・技能の1項目 |
| 列 | スキルを状態ごとに並べる縦の区画。デフォルトは「未習得」「習得中」「習得済み」。追加と名前変更はできるが、削除はできない |
| 習得済み列 | 特別な列。ここへ移動したスキルに習得日が記録される。名前は変更できるが、この列の役割は変わらない |
| 習得日 | スキルが習得済み列に入った日。自動で記録され、編集できない |
