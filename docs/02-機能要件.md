# 02. 機能要件

## 1. 機能一覧

| ID | 機能 | 概要 |
|---|---|---|
| F-01 | ボード表示 | 3つの列とスキルを1画面に表示する |
| F-02 | スキル追加 | 列を指定してスキルを追加する |
| F-03 | スキル編集 | スキルの項目を編集する |
| F-04 | スキル削除 | スキルを削除する |
| F-05 | スキル移動 | ドラッグ&ドロップで、列間の移動と列内の並び替えをする |
| F-06 | 習得日の自動記録 | 習得済み列への移動で習得日を記録し、戻すと消す |
| F-07 | 優先度順の並べ替え | 未習得・習得中の列を、優先度の高い順に並べ替える |

> **列は「未習得」「習得中」「習得済み」の3つに固定する。** 列の追加・名前変更・削除の機能は設けない(画面にも API にも用意しない)。

## 2. 機能の詳細

### F-01 ボード表示

- 画面を開いたとき、3つの列を左から「未習得」「習得中」「習得済み」の順に表示する
- 各列に、その状態のスキルを並び順の昇順に表示する
- スキルがない列は、空の状態で表示する
- 習得日は、**習得済み列のカードにだけ**表示する(未習得・習得中のカードには表示しない)

### F-02 スキル追加

- **未習得と習得中の列**に「スキル追加」ボタンを置く。習得済み列には置かない(習得済みにするには、追加したスキルを移動する)
- 追加時の入力項目: スキル名(必須)、ポイント・考察、優先度、期限
- 追加フォームに、習得日の欄は出さない
- 追加したスキルは、指定した列の末尾に置く
- 習得済み列には直接追加できない(API も、習得済みを指定した追加を 422 で拒否する)
- 初期値: 優先度は「中」、期限は空、ポイント・考察は空

### F-03 スキル編集

- カードから編集できる項目: スキル名、ポイント・考察、優先度、期限
- **習得日は編集できない**(画面に入力欄を出さず、API も受け付けない)
- 編集フォームに習得日を出すのは、**習得済みのスキルの場合だけ**(読み取り専用で表示する)
- スキル名を空にして保存することはできない

### F-04 スキル削除

- 各カードに削除ボタンを置く
- 誤操作を防ぐため、削除の前に確認ダイアログを出す
- 削除すると、同じ列のスキルの並び順を詰める

### F-05 スキル移動

- カードをドラッグ&ドロップして、別の列や、同じ列内の別の位置に移動できる
- 移動が成功したら、移動元と移動先の並び順を振り直す
- 画面は先に更新し(楽観的更新。保存の完了を待たずに画面へ反映する方式)、保存に失敗したら元の位置に戻してエラーを表示する

### F-06 習得日の自動記録

| 操作 | 習得日の扱い |
|---|---|
| 習得済み列以外 → 習得済み列へ移動 | 移動した日(サーバー側の日付)を記録する |
| 習得済み列 → 習得済み列以外へ移動 | 消す(空に戻す) |
| 習得済み列内での並び替え | 変更しない |
| 習得済み列以外の列どうしの移動 | 変更しない(空のまま) |

- 記録するのは、サーバーが決めた日付のみ。クライアントが送る値は使わない
- 習得日はデータとしては習得済みのスキルにだけ入る。画面に表示するのも、習得済み列のカードだけ

### F-07 優先度順の並べ替え

- **未習得と習得中の列**の見出しに、「優先度順」ボタンを置く。習得済み列には置かない
- ボタンを押すと、その列のスキルを **高 → 中 → 低** の順に並べ替える
- 同じ優先度のスキルどうしは、並べ替える前の並び順を保つ
- 並べ替えた結果は保存される(再読み込みしても保持される)
- 並べ替えは、ボタンを押した時点の1回だけ行う。並べ替えのあとに追加・移動したスキルを、自動で優先度順に並べ直すことはしない(追加は末尾に置く)
- 並べ替えのあとも、ドラッグ&ドロップ(F-05)で、手動で順番を変えられる
- 他の列には影響しない

## 3. データ要件

詳細は [05-ER図.md](05-ER図.md) を参照。

| 項目 | 制約 |
|---|---|
| スキル名 | 必須、100文字以内 |
| 状態 | 未習得 / 習得中 / 習得済み のいずれか(列にあたる) |
| ポイント・考察 | 任意、5,000文字以内 |
| 優先度 | 高 / 中 / 低のいずれか |
| 期限 | 任意、日付 |
| 習得日 | 自動記録のみ、日付。習得済みのスキルにだけ入る |
| 並び順 | 同じ状態の中で 0 から連番 |

## 4. 非機能要件

| 項目 | 要件 |
|---|---|
| 操作性 | 画面遷移なしの1画面で、すべての操作が完結する |
| 性能 | スキルが数百件あっても、操作が引っかからない(ボード全体を1回の API で取得する) |
| データ保持 | 再読み込みしても、スキル・状態・並び順・習得日が保持される |
| 整合性 | 移動や並べ替えでの並び順の更新と、習得日の更新は、1つのトランザクション(まとめて成功か失敗かを決める処理単位)で行う |
| 対応ブラウザ | 最新版の Chrome、Safari、Edge(デスクトップ) |
| セキュリティ | SQL インジェクションと XSS への対策(Rails と React の標準機能を使う)。CORS は許可するオリジンを限定する |
| コスト | AWS の無料利用枠内。詳細は [06-技術スタック.md](06-技術スタック.md) |
| テスト | API のテスト(RSpec)で、F-05、F-06、F-07 のルールを検証する |

## 5. API 一覧(概要)

すべて `/api/v1` 配下。列を扱う API は設けない(列は固定のため)。

| メソッド | パス | 機能 |
|---|---|---|
| GET | /skills | F-01 すべてのスキルの取得(状態、並び順の順) |
| POST | /skills | F-02 スキル追加(リクエストで状態を指定する。習得済みは 422) |
| PATCH | /skills/:id | F-03 スキル編集 |
| DELETE | /skills/:id | F-04 スキル削除 |
| PATCH | /skills/:id/move | F-05、F-06 スキル移動(状態と並び順を指定する) |
| POST | /skills/sort | F-07 優先度順の並べ替え(状態を指定する。習得済みは 422) |

### GET /skills のレスポンス

スキルの配列(JSON)を、状態(未習得 → 習得中 → 習得済み)、同じ状態の中では並び順の昇順で返す。スキルがなければ、空の配列 `[]` を返す。画面側で、状態ごとに列へ分ける。

```json
[
  {
    "id": 4,
    "name": "受発注システムの操作",
    "note": "手順書を先に読む。",
    "status": "unlearned",
    "priority": "high",
    "due_date": "2026-09-10",
    "acquired_on": null,
    "position": 2
  }
]
```

| 項目 | 型 | 内容 |
|---|---|---|
| id | 数値 | スキルの ID |
| name | 文字列 | スキル名 |
| note | 文字列 または null | ポイント・考察 |
| status | 文字列 | 状態。`unlearned`(未習得)/ `learning`(習得中)/ `mastered`(習得済み) |
| priority | 文字列 | 優先度。`high`(高)/ `medium`(中)/ `low`(低) |
| due_date | 文字列 または null | 期限(`YYYY-MM-DD`) |
| acquired_on | 文字列 または null | 習得日(`YYYY-MM-DD`)。習得済みのスキルにだけ値が入る |
| position | 数値 | 同じ状態の中の並び順(0 始まり) |

項目名は、Rails の慣習どおり `snake_case`(小文字と下線)にする。作成日時・更新日時は返さない。
